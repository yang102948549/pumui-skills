# 품의담기

사용자가 열어 둔 쇼핑몰 장바구니의 **현재 선택된 상품만** 품목내역 엑셀서식으로 옮긴다. 특정 사이트의 선택자나 과거 상품·가격을 다른 실행에 재사용하지 않는다.

## 원본과 장바구니 확인

- 사용자가 서식을 지정하면 그 파일을 사용하고, 지정하지 않으면 이 스킬의 `assets/품목내역(통합).xls`를 원본 서식으로 사용한다. 실제 머리글과 입력 위치를 읽는다. 원본이 여러 개면 정확한 대상만 확인한다. 새 파일을 원본 서식으로 잘못 선택하지 않는다.
- 브라우저 도구의 현재 탭과 접근성 트리/DOM을 읽는다. 로그인되지 않았거나 빈 장바구니이면 상품이 없다고 단정하지 말고 로그인 상태를 확인한다. 사용자가 로그인하여 상품을 준비할 때까지 실제 상품 테스트는 미완료로 기록한다.
- 선택 체크박스와 쿠폰 체크박스를 구분한다. 판매자 전체선택만 믿지 말고 개별 상품의 선택 상태를 확인한다. 추천 상품, 미선택 상품, 품절·구매 불가 상품을 임의 포함하지 않는다.
- 선택된 각 행의 상품명, 옵션, 수량, 표시 가격, 가격이 개당인지 행 전체인지, 판매자/배송 묶음, 상품 링크를 수집한다. 옵션은 구별에 필요한 경우 내용에 괄호로 덧붙이고 규격·단위에 넣지 않는다.
- 가격은 현재 장바구니에 실제 적용된 할인 후 상품 가격을 기본으로 한다. 취소선 정가, 단위무게당 가격, 적립 예정액, 조건부 카드 혜택을 단가로 쓰지 않는다. 할인 전 금액을 요청받으면 그 지시를 따른다.
- 행 금액이면 수량으로 나누어 단가를 구한다. 나누어떨어지지 않아 원 단위 반올림으로 총액이 바뀌는 경우 임의 반올림하지 말고 단가 정밀도와 서식 허용 여부를 확인한다. 불명확한 가격 의미는 화면 상세로 확인하며 추측하지 않는다.

## 엑셀 입력 규칙

| 열 | 값 |
| --- | --- |
| 내용 | 상품명 |
| 규격 | 빈칸 |
| 단위 | 빈칸 |
| 수량 | 장바구니의 숫자 수량 |
| 예상단가 | 상품 1개/주문 단위의 숫자 가격 |

상품명에 포함된 묶음 개수(예: 10개입)를 주문 수량에 다시 곱하지 않는다. 상품 행은 옵션·가격이 다른 행끼리 임의 병합하지 않는다.

### 배송비도 품목으로 입력

- 선택 상품에 실제 부과되는 **배송 묶음별 배송비 한 건**을 수집한다. 동일 판매자의 묶음배송비를 상품마다 중복 세지 않는다. 추가 지역 배송비 등은 실제 표시되어 확정된 금액만 포함한다.
- 금액이 같은 배송비는 내용 `배송비`, 수량 `부과 건수`, 예상단가 `해당 금액`의 한 행으로 합친다. 다른 금액은 별도 행으로 추가한다.
- 예: 3,000원 두 건과 2,500원 한 건이면 `배송비 / 빈칸 / 빈칸 / 2 / 3000`, `배송비 / 빈칸 / 빈칸 / 1 / 2500`이다.
- 무료배송(0원)은 비용 행으로 추가하지 않는다. 배송비가 미정이면 0원으로 대체하지 말고 미확정임을 알린다.
- `scripts/group_shipping.py`는 화면에서 확인한 배송 묶음 목록을 금액별로 집계한다. 상품별 중복 목록을 입력해서는 안 된다.

## 저장과 검증

- 해당 엑셀 파일 작업 스킬을 적용한다. 기존 열 순서·머리글·시트·서식·수식을 유지하고 지정 입력 영역만 채운다. 요청하지 않은 합계 열·안내 행·출처 시트를 추가하지 않는다.
- XLS 파일을 XLSX로 이름만 바꾸지 않는다. 기본 도구가 XLS를 지원하지 않으면 형식을 보존하는 XLS 라이브러리를 사용한다. 수식 등 보존 불가능한 기능이 있으면 다른 도구로 전환한다.
- 원본 서식을 보존하는 결과 사본을 저장한다. 기존 결과 파일이 열려 있어 저장이 거부되면 사용자 앱을 닫거나 종료하지 말고 다른 결과 파일명으로 저장한다.
- 저장된 파일을 다시 읽어 모든 상품명·수량·단가, 규격·단위 공란, 배송비 집계, 행 누락·중복을 확인한다. 숫자는 텍스트가 아닌 숫자형이어야 한다.
- 상품별 `수량 × 단가` 합계와 배송비 합계가 선택 장바구니 요약과 일치하는지 검증한다. 주문 전체 할인 등이 있어 불일치하면 원인을 확인하고 임의 배분하지 않는다.
- 최소 주문금액 부족 안내는 배송비가 아니다. 표시된 배송비만 입력하고, 구매 조건 미충족은 사용자에게 별도로 알린다.
- 열 너비를 임의 재설계하지 않되, 긴 상품명의 표시가 잘리면 최소한의 줄바꿈·행 높이 조정 또는 사용자 서식 요구를 따른다. 데이터 전체 보존과 화면 표시 검증을 구분한다.
- 최종 응답에는 결과 파일 링크, 적용 가격 기준, 배송비 포함 총액만 간단히 제시한다.

## 다른 사이트 테스트

사이트 이름만 바꾼 모의 데이터 테스트를 실제 사이트 성공이라고 보고하지 않는다. 다음 상태를 구분해 기록한다.

1. 페이지 접근 성공
2. 로그인된 실제 선택 상품·수량·가격·배송 묶음 판독 성공
3. 엑셀 저장 후 재조회와 장바구니 총액 대조 성공

테스트하려고 사용자 장바구니에 상품을 추가하거나 선택 상태·수량·쿠폰을 바꾸지 않는다. 필요한 테스트 상품 준비를 요청한다. 빈 장바구니·로그인 차단·접근 차단은 실제 상품 처리 성공이 아니다.
