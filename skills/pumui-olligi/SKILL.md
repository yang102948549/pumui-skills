# 품의올리기

## 시작할 때 받는 정보

- 품의담기에서 만든 결과 엑셀 파일. 후보가 여럿이면 파일명·행 수·금액으로 구분해 확인한다.
- 사용할 예산. 사용자가 처음부터 지정할 수 있도록 안내한다. 세부사업·세부항목·원가통계비목·산출내역으로 대조하고, 같은 이름의 예산이 여러 개면 후보를 제시한다. 이전에 선택된 예산을 현재 지시로 간주하지 않는다.
- 제목은 사이트의 별도 필수 항목이다. 사용자가 주지 않았다면 함께 묻는다. 회계연도·요구일자·완료요구일자는 현재 값과 사용자 지시를 대조하고 임의 변경하지 않는다.
- 로그인된 현재 브라우저를 사용한다. 이 스킬 호출은 지정된 파일을 지정 사이트에 업로드하고 개요 및 예산을 입력하는 요청이다. 같은 작업의 승인을 반복해서 묻지 않는다.

## 개요 생성

엑셀의 실제 내용·수량·예상단가 열을 읽는다. 머리글·빈 행·합계 행을 제외한 품목 행을 세며 배송비 행은 포함한다. 수량 합계가 아니라 행 수로 종류를 계산한다. 금액은 모든 품목의 수량 × 예상단가 합계다.

```text
1. 관련:
2. 운영물품을 아래와 같이 구입하고자 합니다.
  가. 품목: {첫 번째 항목명} 외 {품목 행 수 - 1}종
  나. 금액: {천 단위 쉼표를 넣은 총금액}원.  끝.
```

`1. 관련:` 뒤는 비운다. 연도·교과·활동명을 2번 문장 앞에 자동 삽입하지 않는다. `원.` 뒤 공백은 정확히 두 칸이다. 한 품목만 있으면 `외 0종` 대신 첫 항목명만 기재한다.

첫 번째 내용 셀을 기준으로 하되 임의로 브랜드명만 남기지 않는다. 사이트는 개요 300Byte 제한을 표시한다. 입력 전 길이를 고려하고 입력 후 실제 값과 Byte 표시를 확인한다. 길이 제한을 넘거나 잘리면 사용자가 지정한 대표 품목명으로 줄인다. 대표명 합의 없이 잘린 문자열을 완료로 처리하지 않는다.

## 화면 흐름

브라우저 사용 지침을 적용하고 현재 접근성 트리/DOM에서 컨트롤을 찾는다. 화면 번호와 동적 ID를 다른 실행에 그대로 재사용하지 않는다.

1. 업무관리+ → 학교회계 → 사업관리 → 사업담당 → 품의/정산 → 품의등록. 이미 해당 화면이 열려 있다면 현재 입력을 보존하고 이어간다.
2. 개요 입력란에 위 서식을 입력하고 읽어 확인한다. 제목은 개요와 별도 필드다. `기본문구적용`으로 사용자 서식을 덮어쓰지 않는다.
3. `예산선택` 팝업에서 지정 예산을 조회한다. 부서명, 세부사업, 세부항목, 원가통계비목, 산출내역으로 대상 행을 대조한다. 소계·총계 행은 대상이 아니다. 잔액을 확인하고 해당 행을 선택한 뒤 `확인`을 눌러 본 화면의 예산내역과 대조한다. 예산이 모호하거나 잔액이 부족하면 임의 대체·분할하지 않는다.
4. **품목내역**의 `파일업로드`를 누른다. 아래의 `첨부파일추가`나 `품목내역 파일 다운로드`와 혼동하지 않는다.
5. `엑셀업로드` 팝업에서 `파일`(접근성 이름: 엑셀업로드)을 눌러 파일 선택기를 열고 정확한 결과 파일을 업로드한다. 파일 선택 이벤트를 클릭 전에 기다리는 지원 API를 사용한다. 일반 양식에 `S2B업로드`를 선택하지 않는다.
6. 팝업 표에 들어온 내용·규격·단위·수량·예상단가·예상금액을 원본과 비교한 뒤 팝업의 **확인**을 누른다. 파일을 골랐다는 것만으로 업로드 완료가 아니다.
7. 본 화면의 품목내역 행과 요구금액을 재조회해 원본 및 개요 금액과 대조한다. 배송비 수량·단가·금액도 확인한다. 재시도 전에 기존 반영 여부를 확인해 중복 업로드를 피한다.

## 완료 범위

사용자가 정한 기본 완료 지점은 개요·예산·엑셀 품목을 등록 화면에 반영한 상태다. 저장과 결재요청은 별도 동작이다. 지시가 없다면 누르지 않고 `화면 반영 완료, 미저장`처럼 상태를 정확히 알린다. 파일 업로드 팝업의 확인은 이 범위에 포함되므로 다시 허락을 묻지 않는다.

실제 입력을 바꿨다면 결과 스크린샷과 간단한 결과를 제공한다. 확인하지 않은 단계는 검증 완료로 기록하지 않는다. 사용자 기존 입력을 검토할 때 신규·삭제·초기화로 없애지 않는다.
